I documented how `glab stack sync` works when you use a forked repository, after the related bug fix shipped.

The bug fix stopped broken merge requests, but users still needed a clear answer to two questions: why does the tool ask fork users to choose a repository, and which one should they pick?

I updated the CLI docs to explain:

- when the prompt appears if you work from a fork,
- how to pick the correct remote safely,
- and how this stops you from syncing to the wrong project.

This was my first merged open source contribution. It went through normal maintainer review before merge.
