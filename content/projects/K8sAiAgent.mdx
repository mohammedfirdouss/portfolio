AI Kubernetes Troubleshooting Agent is a platform that debugs a Kubernetes cluster for you. You click "Investigate", it gathers evidence from the cluster, an AI agent reasons over that evidence, and you get back the root cause, a suggested fix, and a confidence score. Every investigation is saved, so the team can look back at past incidents.

## What it is

A Kubernetes debugging assistant with:

- **Automatic investigations:** One request kicks off checks on pods, logs, events, deployments, and networking.
- **Root cause analysis:** An LLM reads the collected evidence and names the main problem, such as an OOMKilled container or a service selector mismatch.
- **Suggested fixes:** Each diagnosis comes with a concrete next step, like a kubectl command or a YAML update.
- **History and live progress:** Past investigations are stored, and the dashboard shows each step as it runs.

## How it's built

- **Investigation layer:** Five inspectors that talk to the Kubernetes API and collect debugging evidence.
- **AI agent:** A prompt builder, LLM reasoning through OpenRouter (Claude, GPT, DeepSeek), a root cause analyzer, a fix engine, and confidence scoring.
- **Backend:** InsForge for auth, APIs, investigation history, and realtime updates.
- **Frontend:** A public web dashboard to start investigations and view results.

## Example

A checkout API keeps restarting under load. The agent checks pod status, collects logs, and reads events. It finds the container was OOMKilled: the memory limit is 128Mi but the app peaks near 300Mi. It suggests raising the limit to 512Mi and adding memory alerts, with 91% confidence.
