My old domain expired, so this site needed a home while I get a new one. Instead of waiting, I set up GitHub Pages as a temporary deployment target next to the existing Cloudflare Pages setup. Here is what that involved.

## Why Run Two Deployments

The site already deployed to Cloudflare Pages as a static export on every push to `master`. Instead of removing that, I added GitHub Pages as a second, independent deployment target:

- Cloudflare keeps deploying exactly as before. That workflow does not change.
- A new GitHub Actions workflow builds the same static export and publishes it to GitHub Pages.
- Once I have a new domain, I can drop the GitHub Pages deployment without touching anything on the Cloudflare side.

## Making One Build Work for Both Hosts

The two hosts do not serve the site from the same place. Cloudflare serves it from the domain root. GitHub Pages serves a project site from a `/portfolio` subpath, because the URL is `username.github.io/portfolio`. Next.js handles this with `basePath` and `assetPrefix`. But these values must be different for each host, while the code stays the same.

### Conditional Base Path

The fix was one environment variable, read at build time:

```js
const isGithubPages = process.env.GITHUB_PAGES === "true";

const nextConfig = {
  basePath: isGithubPages ? "/portfolio" : undefined,
  assetPrefix: isGithubPages ? "/portfolio/" : undefined,
};
```

The GitHub Pages workflow sets `GITHUB_PAGES=true` before the build. The Cloudflare workflow does not set it at all, so it keeps the root-relative behavior it already had.

### Static Export and Image Optimization

The built-in Next.js image optimizer needs a server to run on. Neither host has one for this static export. So any use of `next/image` in the app would silently return a 404 in production. Setting `images.unoptimized: true` was the fix. This was arguably already a hidden bug on Cloudflare — it just had not been noticed yet.

## What's Next

Once I buy a new domain and point it at Cloudflare, the GitHub Pages workflow and this temporary URL go away, and the main site URL switches back. Until then, this is the live version.
